surface:
  - name: actorOf
    shape: (request) -> {personId}, or throws a stable AbstractException subclass
    transport: >-
      GraphQL request header "Authorization: Bearer <sessionToken>" (RFC 6750 bearer-token form). The
      token itself stays this app's own opaque, Postgres-backed session id (sds.login.session-store),
      not a Keycloak-verified JWT, but the header name and value shape match nivo-fe/nivo-backend's own
      convention for presenting an access token (nivo-fe apps/app/src/modules/api/graphql.ts sends
      "authorization: Bearer <token>"). A missing header, an empty token, or a value with no "Bearer "
      prefix all resolve to the empty string before any session lookup and are refused by
      SessionNotFoundException before the lookup ever queries Postgres (session.service.ts#findActive) -
      this is the fix for the auth bypass a real-browser uat.verify run found against the pre-refactor
      REST controllers, where an absent header reached findOneBy({ token: undefined }) and TypeORM
      silently matched an arbitrary session row instead of refusing. Rev 1/2 of this contract left the
      header name implicit as the pre-refactor REST controllers' x-session-token, and rev 2's own
      withdrawn text never named a header at all; this is the first revision to name the wire mechanism
      as part of the surface, which is what let the original mismatch (frontend sending "Authorization:
      Bearer", backend reading "x-session-token") go undetected until a live run caught it.
    guarantee: Resolves to the person of a live session. An absent or expired session throws
      SessionNotFoundException/SessionExpiredException (both AbstractException, both carrying a stable
      `code`) rather than returning a sentinel value; it never returns a partial person.
    stability: A change to the shape, to the transport header name/value shape, or to which exception
      subclass is thrown for which cause, is breaking for task.
guarantees:
  - A returned personId belongs to a session that was live at the moment of the call.
  - An absent/expired session is a thrown, typed refusal, never "unknown" and never a null the caller
    could mistake for success; task must not retry on it.
consumerObligations:
  - task lets the thrown exception propagate as its own refusal (unauthenticated) and never invents an
    actor to keep going.
  - task does not cache the personId beyond one request.
