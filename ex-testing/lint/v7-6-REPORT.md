### Why every write was preceded by a measurement pass

`scripts/example-evidence.mjs` reports only an exit code, and on this tree an exit code of 0 does **not**
mean a test ran: `npx jest -t "<filter>"` exits 0 with `Tests: 701 skipped, 701 total` when the filter
matches nothing, and jest/vitest print their summaries on **stderr**, which `execFileSync` never returns.
So this lane first ran every assertion itself (`v76-probe.mjs`, 153 command executions, full logs under
`v76-probelogs/`), parsed the summary line out of the captured stdout+stderr, and only fed records whose
every assertion exited 0 **and selected at least one test** to the tool. That guard is what caught the
`recur` record below; without it the lane would have written a fresh green digest over a run that
executed nothing. Prediction and execution agreed: 60 predicted READY → 61 written (one more record's
inventory entry appeared after the dry run), 0 live failures needing restore.

## Tooling / host findings worth carrying (from `--help` and source, as step 1 requires)

- `node scripts/example-evidence.mjs --help` → `REFUSED unrecognized argument: --help`; the tool has no
  help and no `--dry-run`. It takes `--work --record --cwd --assert <id>=<command>` (repeatable), writes
  `recordDigest`/`codeDigest` itself, and **exits 1 if any assertion is nonzero — while still having
  already written the file**. Any wrapper must therefore restore on nonzero, or a probe failure silently
  replaces good evidence with a red file. Both tools resolve every relative path against the `.claude`
  host root, and `--assert <id>` must be the record's own `ac.*`/`contract.*` id or `example-verify.mjs`
  reports a result for an id no one declared.

  workspace-root _local runtime state and workspace-root _resources typed custody; collocate all other
  owned YAML records and assets with their node."}]` (stack trace, exit 1). Pass `--work` explicitly.
- The brief's "the tool re-runs the record's assertions" is only true of the `--assert` pairs the caller
  passes: nothing reads `requiresProof` off the record, so the commands come out of the *old evidence
  file* (as v6-4 Q2 already noted, the `--cwd` they ran under is not stored either — this lane inferred
  it per record: fe impl records → `examples/todo-app-frontend`, `node verify-captures.mjs` → fe root,

  `examples/todo-app-backend`). A `--from-record` flag that reads `requiresProof` would remove both this
  inference and the substitution step above.

  Work node's ownership rule has one implementation") and ends with a `main()` plus a
