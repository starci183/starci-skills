# v8-3 — `scripts/check-work-history.mjs` (change/rev discipline via git)

The Work tree keeps no history, so `change.rev`/`kind`/`withdraws` claims are unverifiable in place — v6-4 showed `checks/work-change.mjs` exists but needs a baseline tree handed to it. Git IS the baseline (`.claude` is a git repo; the example trees are committed). Build the bridge.

Script: `scripts/check-work-history.mjs`

Checks:
- **REV_NOT_BUMPED**: for each record file, `git log --follow --format=%H -- <path>` → diff the previous committed version's normative projection (same projection as check-work-deep: strip state/change/provenBy/verificationSource/blockedBy) vs current. If normative content changed but `change.rev` didn't bump → REFUSE `CHANGE_UNRECORDED`.
- **REV_NOT_MONOTONIC**: rev decreased across history → REFUSE.
- **WITHDRAWS_NOT_VERBATIM**: `change.withdraws[]` entries must be verbatim strings from the previous version's `statements[]` (or normative list fields). Compare against the actual previous blob — v6-4 noted this is only checkable via git.
- **CHANGE_KIND_SUSPECT**: declared `kind: editorial` but statements added/removed → SUSPECT (classify like checks/work-change.mjs does: verbatim-held previous entries + additions = clarifying; removals/rewrites = breaking).
- **UNTRACKED_RECORD**: record files with no git history at all (never committed) → INFO count (v7 lanes are mid-flight; untracked is expected right now).
- Git ops: `git log`/`git show` via child_process, cwd = the `.claude` repo root (find it by walking up to `.git`). Graceful: if a tree isn't inside a git repo, INFO-skip rather than refuse.
- `--limit <N>` to bound log depth (default: first-parent, 50 commits) — keep it fast.

Done → `done/v8-3.done` + report.
