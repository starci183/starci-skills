# v8-1 — `scripts/check-work-replay.mjs` (evidence replay engine)

The audits' core complaint: evidence files pin digests but nothing re-executes the assertions — "stale" is a verdict with no replay button. Build the replay layer.

Script: `scripts/check-work-replay.mjs`

Behavior:
- Walk evidence.yaml files across both example trees. For each assertion with a `command`, parse it into an executable spec: `{command, cwd}` — cwd resolution order: `assertion.cwd` → `evidence.cwd` → the record's `repository` resolved via `repoRootFor` → the backend root. Log a SUSPECT `ASSERTION_NO_CWD` when falling back beyond the record's own repository.
- `--dry-run` (default): do NOT execute — for each assertion report `REPLAYABLE` (command+spec path exist) or `NOT_REPLAYABLE` (dead command/path — overlap with check-work-deep's PROOF_COMMAND_DEAD is fine, but resolve cwd correctly across bound repos: a record's `repository` field may make it a frontend command).
- `--run <recordId|--all>`: actually execute assertions via `child_process.spawn` (shell:false where possible, `cmd /c` on Windows for npm scripts), capture exit code + tail of output, and report `REPLAY_PASS`/`REPLAY_FAIL` per record. Never mutate evidence.yaml — replay is read-only; re-capture belongs to example-evidence.mjs.
- Support a `--record <id>` filter and a summary: `N replayable, M dead, K executed (P pass / F fail)`.
- Timeouts: default 120s per assertion, `--timeout <s>` override. Kill cleanly on timeout; report as REPLAY_TIMEOUT not a crash.
- This will be the heaviest script — keep execution behind explicit flags; default invocation must be fast and side-effect-free.

Coordinate: v7 lanes are editing records while you build — run your verification passes but expect record churn; report findings as a snapshot.
Done → `done/v8-1.done` + report.
