## Checks
- **SIBLING_CAPABILITY_IMPORT (LAYERING-3, the one canon defers)**: build the module graph — parse every `src/**/*.ts` import, resolve aliases (`@modules/`, `@features/`…), and refuse imports that cross into a sibling capability's internals (anything not its declared public surface). Capability roots: `src/modules/<cat>/<cap>/`, `src/features/<f>/`. Category folders (platform/lib/integrations) hold capabilities at the SECOND segment — read module-layering.mjs's META_ROOTS note before coding this; getting it wrong misreads barrels.
- **ORPHAN_SOURCE**: every `src/**/*.ts` (excluding node_modules/dist/tests-infra as declared) must sit under some record's resolved owners (reuse `resolveOwnedDirs` per record over both trees) OR a declared exemption. Exemptions come from a declared list — check `workspace.yaml`/`.starciwork` for an existing exemption convention; if none exists, read `ALLOWLIST`/`exemptions` from a `_resources`-adjacent yaml you document, and count exempted files as INFO. Never hardcode "health is fine" in the script.
- **FOLDER_SHAPE**: per capability dir under `src/modules/`, expected skeleton (module.ts, contracts/providers or spec files) — derive the expected shape from what the existing well-formed capabilities share, not from your invention; deviations → SUSPECT with the convention named. Same for `src/features/*/graphql/{queries,mutations}/<cap>/<op>/` — each op dir's expected file set.
- **NAMING_DRIFT**: kebab-case filenames, `*.handler.ts`/`*.resolver.ts`/`*.controller.ts`/`.spec.ts` suffix conventions actually used in the repos — flag outliers as SUSPECT. Bonus honest finding: `src/modules/bussiness` is a typo'd canonical dir — report it as INFO `CANON_DIR_TYPO` (rename is v8-5's tool's job, not yours).
- **TEST_LAYOUT**: specs/e2e/infra live under `src/tests/{unit,e2e,infra}` + `uat/` at repo root for the fe app — specs outside the layout → SUSPECT.
- **FE counterpart** (todo-app-frontend + ecommerce-app-fe): `src/app/[lang]/` routes are thin shells (page.tsx should delegate to components/pages surfaces — flag pages containing logic beyond composition as SUSPECT), components sit in declared tiers (packages/shared `leaves|composites|branches` or `src/components` tiers per file-layout.md).
