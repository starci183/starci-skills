## Record

Join the demand contract with observed source capability into one approval-ready revision. Name every proposed file, responsibility, change kind, dependency, pattern situation, source evidence, test case, gate, exclusion, and acceptance proof before any product write.

## Compilation law

Every behavior maps to at least one exact path and test. Every path maps back to behavior and to fixed backend pattern situations. Existing owners are reused when their contracts fit; a new family is declared explicitly when no precedent exists. Alternatives and their trade-offs remain in the plan so approval knows which boundary it is selecting.

The canonical JSON form is hashed. Revision identity includes demand hash, source receipts, pattern bindings, exact boundary, and test matrix. Unbound behaviors, decorative rules, unspecified files, stale evidence, or a required path outside allowed roots block compilation.
