## Job

Draw one surface’s business-grounded PNG concepts before frontend implementation, then preserve the resolved direction as an exact typed handoff.

## Done when

Done when the `frontend-art-direction` binds the frozen brief, actual PNG/prompt provenance, Grammar adoption and the selected direction ready to be displayed before frontend implementation.

## Drawing inputs and concept

The request freezes request/art-direction-brief.json under frozenInputs, following [art-direction-brief.schema.json](../../templates/kinds/art-direction-brief.schema.json). Business purpose, actors, journey, actions, information and required states have actual approved or observed source references. Examples stay labelled; unknown necessary inputs stop before ImageGen. Inspiration is not feature, metric, testimonial or permission authority. Each concept states its central idea, story, tone, art style, hierarchy and coherent imagery language, mapped to business journeys and Grammar-owned regions.

Every region’s imagery plan decides its purpose, subject, coherence, reuse, medium, prominence, placement, responsive/accessibility and delivery constraints. Brand or atmosphere is a valid purpose. Rich imagery may span many sections; there is no hero-only template or global asset-minimization rule. Controls, tables and live data remain native. The full-page PNG guides implementation; separately usable assets have their own specifications and provenance.

## One direction authority

Grammar owns component geometry, tokens and icon contracts. Resolve an incompatible drawing before selection; never turn it into arbitrary application CSS. The ImageGen prompt contains the complete frozen brief and the exact concept; a generic beauty prompt is insufficient. PNG file integrity, dimensions and prompt provenance are checked by [art-direction.mjs](../../scripts/art-direction.mjs). The image is reviewed against the business-to-region acceptance mapping. Semantic quality and truthful external tool attribution remain accountable review, not conclusions hashes can prove.

## Selection and presentation

The interaction policy owns candidate counts. By default draw exactly one PNG, publish it as a done visual direction, print it inline and continue without a user question or fabricated choice. Only an explicit compare request enables multiple directions and actual user selection. An unselected comparison sheet ends blocked DIRECTION_CHOICE_REQUIRED with its exact tier-choice options and candidate PNGs. Run node scripts/art-direction.mjs present &lt;branch>, emit that actual Markdown with native PNG embeds, then record the actual answer through node scripts/art-direction.mjs answer &lt;branch> &lt;actual-answer.json>. The answer binds selectedBy:user, sourceRef, presentationSourceRef and presentationHash of that exact embedded sheet. A URL-only sheet cannot satisfy it. After emitting either a selected result or the default PNG, record its actual display through node scripts/art-direction.mjs shown &lt;branch> &lt;display.json>; display.json binds sourceRef and presentationHash. The normal comparison resume binds the original decision id and selected option, reuses the exact candidate bytes and publishes selected PNG as outcome.primary. A validator verifies the retained presentation and attribution, not whether a human physically viewed it.

This operator writes only its branch response artifacts. It writes no frontend source, starts no implementation server and overrides no backend or coordination owner.

## Explicit visual acceptance

Before ImageGen, the brief's visual contract enumerates every required region element and separately usable asset by stable identity. Record native controls, semantic icons with their meaning and bound registry glyph, and code-native connectors with their actual endpoint identities. Freeze anatomy, per-viewport width/height bounds, responsive arrangement and normal/reduced-motion intent. A repeated grid is valid when that is the declared composition. The candidate anchors every element within the actual PNG; a whole strip cannot replace independently declared subjects.

For extracted transparent assets, retain the exact pre-extraction reference and identify enclosed negative space and subject areas that must survive. A transparent sample or alpha minimum does not establish clean extraction. The implementation's [art-direction-adoption](../../templates/kinds/art-direction-adoption.schema.json) requires exact black, white and chromatic composites, plus explicit outer, enclosed, subject, silhouette and edge review. [art-visual-proof.mjs](../../scripts/art-visual-proof.mjs) verifies composite derivation and complete identities; the reviewer must inspect the images against the retained reference. Hashes cannot decide whether a face, white material, fine edge or enclosed region was wrongly removed.

## Operator Result

Show the actual full PNGs inline before explanatory detail and before frontend code. A blocked sheet shows all offered directions and its truthful unanswered choice. A done result embeds the selected PNG first. An image link, prompt text, HTML preview or asset thumbnail is not a substitute.
