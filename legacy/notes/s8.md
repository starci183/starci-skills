## Contract addendum (826894e5): §12 ledger anchor

- Added `tests/ledger-anchor.spec.mjs`: written-at-every-checkpoint, restored-behind-anchor →
  `ledger-behind-anchor`, missing ledger with a tracked anchor → `ledger-missing`, a foreign ledger's bytes
  dropped into the checkout → `ledger-identity-mismatch`, anchor-less first boot is legitimate. **All 5 pass**
  against s0's landed `kernel/ledger-db.mjs` (`writeAnchor`/`readAnchor`/`verifyAnchor`/`anchorFileFor`/
  `ledgerIdOf`/`checkpointLedger`).
- `workflow-restart.spec.mjs` gained two things:
  - an assertion inside the existing §11 test that the anchor (`anchorFileFor(repoRoot)`,
    `readAnchor(repoRoot).workflows[id]`) survives the worktree delete/recreate — it lives in `repoRoot`'s
    `.starciwork`, never in the deleted worktree lane. This is still blocked on the same dependency as the
    rest of that test (see below): nothing writes an anchor yet because `store.saveState` doesn't call
    `writeAnchor` on this branch.
  - a **new, independent** test, `§5/§6 identity: a relocated ledger keeps its machine leases; a path
    rebuilt fresh does not inherit them` — uses `openLedger`/`openMachine`/`reserveTwoPhase`/`machine.sweep`
    directly (no engine/kernel/store dependency), so it is **not** blocked on s2/s3/s9. **Passes standalone**
    against s0's landed identity-by-`meta.ledger_id` sweep.
- Corrections made after reading s0's actual implementation (my first draft guessed the shape from the
  contract prose alone before s0 had shipped it):
  - `verifyAnchor(ledger, repoRoot)` checks **every** workflow head the tracked anchor holds against one
    ledger handle (or `null` for "could not open a ledger at all") — it is anchor-wide, not a
    `{repoRoot,workflowId}` per-workflow call the way I'd first guessed.
  - WAL is the default journal mode now (§3). A raw byte-copy of `runtime.sqlite` is **not** self-consistent
    unless `ledger.checkpoint()` (`PRAGMA wal_checkpoint(TRUNCATE)`) runs first — my restore/foreign-ledger
    scenarios were hitting `no such table: meta` until I added that and cleared `-wal`/`-shm` siblings on
    restore.
  - `machine.sweep()` does **not** orphan-release a lease whose registered path now opens as a *different*
    ledger identity — it treats that the same as "cannot inspect at all" and leaves the lease alone (TTL is
    the only thing that clears it). I had it backwards in my first draft (expected an active release); fixed
    the "rebuilt path does not inherit" test to assert the lease is *kept, unproven-dead* and that the new
    ledger simply never had it, rather than asserting an orphan sweep.
