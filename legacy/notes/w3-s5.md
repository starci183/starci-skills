### Diff 2 — `kernel/common.mjs`, `rulingsText` (blocks every `runLoop`/`launchOp` path — any operation launch
that calls `renderContract`)

```js
export function rulingsText(store){
  const file=path.join(store.dir,'rulings.md');   // store.dir is always null now
  if(!fs.existsSync(file))return '';
  return fs.readFileSync(file,'utf8').trim();
}
```

`store.dir` is `null` unconditionally under the ledger model (`kernel/store.mjs`'s handle literally has
`dir:null`), so this throws `TypeError [ERR_INVALID_ARG_TYPE]` on every call — and it's called from
`jobRulings` (`kernel/common.mjs:476`), which `kernel/kernel.mjs:410`'s `renderContract` calls unconditionally
for every operation contract, and `kernel/verify.mjs:247`'s validator-memory builder. In my test run this
crashed every launch attempt (`kernel-error` event, 3 retries, then the allocator's fake slots stay
permanently "busy" because the exception fires before `release()` — the workflow stalls forever and never
reaches `finished`).

This one I could **not** fully resolve myself: `grep -rn "rulings.md\|'rulings'" --include=*.mjs kernel/ cli/
bin/ hosts/` finds no production *writer* anywhere — `rulingsText` is pure dead-read code today (its only
writer is `tests/workflow-kernel.spec.mjs:4480`, itself via `harness.store.dir` — also broken). docs/ledger-db.md
§4 has no table for "job-wide rulings," so there's no ledger-backed replacement to port to; this looks like a
feature that was never carried into the 1.0.4 schema at all, not a simple field rename. The comment above it
(`Job-wide rulings the user gave at approval time (<store>/rulings.md) travel inside every contract`) reads
like an **owner-authored file the human edits directly** (the same category as `goal.md` or
`.starciwork/workspace.yaml`), which would live under `store.repoRoot` — a property that *does* still exist
on the store — not inside runtime state at all. The narrowest fix I can propose without inventing a new
storage shape:
