# s9 — goal, inputs, schemas, docs, version 1.0.4

## Files changed

- `kernel/goal.mjs`
  - `workflow-goal`/`workflow-amend`/`goal.revise` no longer write `goal.md`/`goal.json` files. All
    three call sites (`planGoalPhase`, `workGoalPhase`, `reviseGoal`) now call `store.setGoal({markdown,json,amendment})`
    and read the current goal back with `store.goal()`. `goal.revise` records the revision body under
    `amendment`, carries the prior markdown forward unchanged (it never touched markdown before
    either), and merges the prior `json` the same way the old file-merge did.
  - `noteLaneInGoal`/`noteCritiqueInGoal` (the lane header and critique splice applied after the goal
    phase returns) now read `store.goal()`, splice the markdown string in memory, and call
    `store.setGoal` again with the same `json`/`amendment` — no more direct file I/O.
  - `stageExternalInputs`: an owner-named external file (an absolute `file:` ref outside the worktree)
    is now put into the ledger's `inputs` table via `store.inputs.put({key,goalRevision,bytes,origin})`
    instead of being copied under `.starciwork/_local/inputs/<workflow>/`. The input's `ref` becomes
    the `ledger://inputs/<workflow_id>/<key>#sha256=<hex>` string `store.inputs.put` returns. This is
    the exact fix for the loss docs/ledger-db.md §4 now records against the `inputs` table comment
    (restart test 2026-09-17 lost two staged inputs because the copy died with the worktree).
  - `quotaSelectedProviders`: the provider-quota-probe file root moved from `path.dirname(store.dir)`
    (today's `.starciwork/_local/workflows`, which no longer exists) to `path.join(store.repoRoot,'.starciwork')` —
    still outside `_local`, so `runtime-budget.json` (Orca's own quota probe, unrelated to the
    ledger's own `budgets` table) is never written under `_local` either.
  - Removed the `readJson`/`writeJson` imports from `common.mjs` (no longer used).
  - goal.md §1 and the return values of `planGoalPhase`/`workGoalPhase` no longer reference
    `store.paths.goal`/`goalJson` (removed by the new store); `next:` messages now point at
    `workflow-export --id <id>` instead of a file path, and both return `goalRevision` (the row's
    `revision` from `store.setGoal`) instead of a path.
- `kernel/inputs.mjs`
  - `recoverWorkflowInputReferences` reads the goal via `store.goal()?.json` instead of
    `store.paths.goalJson`.
  - `reconcileWorkflowInputs`: the input helper's session/launch/server coordination files move from
    `store.dir` (gone) to a new `inputScratchDir(state.id)` = `os.tmpdir()/starci/<id>/`, created on
    demand. `inputs.lock` becomes the ledger signal `inputs-lock` (`store.signal.get/set/clear`,
    scope = workflow id) instead of a lock file; the session record now also carries `repoRoot` so the
    detached helper process can open its own store.
- `kernel/inputs-server.mjs`
  - `serveWorkflowInputs` opens its own `store = createStore({repoRoot:session.repoRoot,id:session.binding.id})`
    and holds/releases the `inputs-lock` signal there (read-then-set, since `signal.set` is an
    unconditional replace — see "Open questions" below) instead of an exclusive-create lock file. The
    liveness check that used to read `<dir>/kernel.lock` now reads the `kernel-lock` signal from the
    same store.
- `schemas/workflow-state.schema.yaml` (new) — documents `state.engine`: `ledgerFile`/`machineFile`,
  and `journalFile` as deprecated-but-allowed only while `ledgerFile` is absent (that combination is
  what `predatesEngineSchema`/continuation read as `ledger-unmigrated`); refuses an engine record
  naming neither.
- `schemas/ledger-db.schema.yaml` (new) — documents the `runtime.sqlite`/`machine.sqlite` table
  catalog of docs/ledger-db.md §4/§5, including `meta` and `inputs` (added once the identity/WAL/anchor
  addendum landed). Explicitly out of scope: `.starciwork/ledger-anchor.json` (§12), which is a
  separate tracked file, not a table.
- `goal.md`
  - New §8 **Persistence**: the ledger DB is the record; `_local` is import/export only (with the
    `inputs` table detail); the machine DB holds only `ai/*` and machine budgets;
    `runtime-budget.json` lives beside the ledger, never under `_local`; worktrees are scratch;
    the anchor is a tracked head, not the record (carries §12's re-clone/refusal behavior verbatim in
    spirit); ignore the ledger file in the host repo's own `.gitignore`, but the anchor is committed.
  - §1 updated: goal writes are a `goals` row via `store.setGoal`, not `goal.json`/`goal.md` files.
  - §3 corrected: `codex-agent` cap 8→10 and its model split (implement/write: luna, verify: sol) —
    this was drift from an unrelated stream's change pulled in by the periodic s0-ledger-db merge, not
    part of this stream's own work; corrected because it's this file's job to stay factual.
- `docs/workflow-kernel.md` — CLI verb list gains `workflow-export`, `op-contract`, `ledger-verify`,
  `ledger-migrate`, `ledger-prune`, `ledger-retire`; the storage paragraph rewritten for the ledger DB,
  including identity/WAL/anchor.
- `SKILL.md` — the one stale `_local/workflows/<id>/` reference (final report) now points at the
  ledger DB / `docs/ledger-db.md`.
- `INDEX.yaml` — `schemas:` folder description now names the two new schema files.
- `package.json` (+ `package-lock.json`, mechanical) — version `1.0.4`.
- `tests/goal-contract.spec.mjs` — new test: `goal.revise` persists a new `goals` row via
  `store.setGoal` (revision increments, `amendment` recorded, markdown carried forward unchanged).
- `tests/execution-contracts.spec.mjs` — new tests: both new schemas compile in strict draft-2020
  mode; `workflow-state.schema.yaml` accepts `ledgerFile`+`machineFile` and a deprecated
  `journalFile`-only state, refuses neither; `ledger-db.schema.yaml`'s table lists are checked against
  the actual `CREATE TABLE` statements in `kernel/ledger-db.mjs` by regex, so the two can never drift
  silently.
- `tests/helpers/pools.mjs` — `GOAL_POOL_CAPS['codex-agent']` 8→10 (same drift as goal.md §3 above).

Branches merged into this one (periodic `s0-ledger-db`, per the contract, twice; plus `main` once when

## Open questions

- **`signal.set` exclusivity.** docs/ledger-db.md §4 documents `signals` with
  `PRIMARY KEY(scope,key)` and s1's implementation is `INSERT OR REPLACE` — an unconditional
  overwrite, not a compare-and-set. I used a read-then-write pattern in `inputs-server.mjs`
  (`signal.get` → check `alive(pid)` → `signal.set`) for `inputs-lock`'s mutual exclusion, which is not
  race-free against two helpers starting at the exact same instant (the old `fs.openSync(...,'wx',...)`
  was atomic). Given the kernel is the only spawner and already serializes spawns per tick, I judged
  this an acceptable, contract-consistent reading rather than inventing a new store primitive outside
  my files — but if a stronger guarantee is wanted, `kernel-lock`/`supervisor-lock`/`inputs-lock` might
  all want a `signal.setIfAbsent` on `kernel/store.mjs` (s1's file), which I did not request since it
  wasn't asked for.
- **`config.json`/`INDEX.md`.** Neither exists under those exact names in this checkout (`config.json`
  is gitignored and created at runtime from `config.example.yaml`; the manifest is `INDEX.yaml`, not
  `.md`). No model-routing change was made to `config.json` (per the contract); `INDEX.yaml`'s load
  order/folder-purpose lines were touched only where they named something this stream's work changed
  (the two new schema files) — I did not find a literal "doc load order" list to update beyond that.
