## What was actually left in this cluster (fixed this wave)

Both are test-fixture ports (`kernel/engine.mjs`/`kernel/admission.mjs` needed nothing further — see
verification below) — no engine.mjs/admission.mjs changes this wave.

### `tests/kernel-engine.spec.mjs` — the other 6 of the "8 remaining 'openLedger needs a file'"

Six `createJobBridge({journalFile:...})` call sites, the same stale field name from wave 1/2's
`tests/engine-adapter.spec.mjs` fixtures. `kernel/job-bridge.mjs`'s real signature is
`{ledgerFile,machineFile,...}` — no `journalFile` alias (unlike the module-level `engine.mjs` functions,
which do accept it via `ledgerFile??journalFile`) — so the field was silently dropped and `openLedger` got
`file:undefined`. Ported all six to `ledgerFile`.

I searched the rest of the test suite for the same shape (`createJobBridge({journalFile` /
`enrollEngine(...journalFile`) and found exactly one more: `tests/goal-contract.spec.mjs:201` —
`enrollEngine(store,state,{journalFile:...})`. Not this cluster (goal.mjs's spec, not one of the five named
here), and `enrollEngine` doesn't accept `journalFile` either — flagged below, not fixed.

I deliberately left `tests/kernel-engine.spec.mjs`'s other failures alone (still ~17 with both cross-stream
fixes applied). They're a different, deeper class: pairing the retired `kernel/journal.mjs` directly with
either an `ai/*`-scoped `admission.reserve(...)` or `kernel/store.mjs`'s `bindJournal(...)`. Both hit an
unconditional `meta`-table lookup one level below anything in `kernel/admission.mjs` can reach —
`kernel/ledger-db.mjs`'s `reserveTwoPhase` (`machine.registerLedger({...,ledgerId:ledger.ledgerId??
ledgerIdOf(ledger)})`, unguarded) and `inspectLedger` (`ledgerId:ledgerIdOf({db})` at open, unguarded), and
`kernel/store.mjs`'s `bindJournal` refusing with `ledger-binding-mismatch`. Wave 2's notes already covered
this in detail; still true, still not a file this cluster owns, still not something a test-fixture rename
can route around (the two-phase primitive's whole design requires a ledger identity the retired module
never had).

### `tests/engine-kernel-flow.spec.mjs` — two more contract mismatches the hand-rolled `store` mock didn't carry

1. **No `store.repoRoot`.** `kernel.mjs`'s `applyOpReport` now writes kernel-only validation evidence under
   `store.repoRoot/.starciwork/kernel-evidence/<workflow id>/evidence/...` — beside the ledger, per §7's
   custody boundary (outside every op's allowlist) — not under `store.dir/evidence/...` where the test's
   own assertion still looked. Added `repoRoot:root` (the fixture's real git worktree) to the store mock,
   excluded `.starciwork/` via `.git/info/exclude` so the new write doesn't show up as untracked in this
   same test's "clean tree" assertion, and pointed the evidence-existence assertion at the new path.
2. **`readReports()`/`stageAnsweredDecisionLateReport` contract.** Real `readReports()`
   (`kernel/store.mjs:213-215`) always adds `dispatchId` (from the `reports` row) alongside whatever the
   raw report JSON itself carries (a `dispatch` field, from `starci/op-report@1`'s own schema).
   `kernel.mjs`'s `stageAnsweredDecisionLateReport` looks the report up by `dispatchId` — the mock only
   returned the raw parsed JSON, so the lookup always missed and every late-decision test failed
   immediately with a generic "late report is not bound to the exact current Run/Task/Dispatch" (the
   `!report` short-circuit, not any of the field checks after it — I checked every one of those by hand
   first and they all matched; the actual miss was the lookup key itself). Fixed by adding the field.
   Getting past that surfaced a second layer: `stageAnsweredDecisionLateReport` hashes the report's
   immutable bytes straight off `store.ledger.db`'s `reports` table (`reportJsonBytes`/`reportDigest` —
   the ledger's replacement for a report file's own sha256), which the mock never populated at all
   (`store.ledger` was `undefined`). Inserted a real `reports` row through the fixture's own open ledger
   handle (`f.runtime.journal`) and set `store.ledger` to it.
