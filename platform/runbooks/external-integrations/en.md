# External integrations

## Use when

Use this page when enabling or rotating a provider that is not created by the local Compose stack.
`scripts/credentials.mjs` is the authoritative mapping from provider purpose to encrypted filename and
application env key.

## Before

Create the provider account/project in its own console, select sandbox/test mode first, record callback
or webhook URLs for the environment, and keep the issued value in a password manager until it is stored.
Do not use `secret:gen`; third-party credentials cannot be regenerated by this repository.

## Secrets

| Family | Fixed encrypted records |
|---|---|
| PayOS / SePay | `payos-api-key.key.enc`, `sepay-api-key.key.enc`, `sepay-ipn-secret.key.enc` |
| Stripe | `stripe-secret-key.key.enc`, `stripe-webhook-secret.key.enc` |
| PayPal | `paypal-client-id.key.enc`, `paypal-client-secret.key.enc`, `paypal-webhook-id.key.enc` |
| NOWPayments | `nowpayments-api-key.key.enc`, `nowpayments-ipn-secret.key.enc` |
| GitHub/data | `github-access-token.key.enc`, `github-secret-key.key.enc`, optional `data-git-token.key.enc` |
| Keycloak app | `keycloak-client-secret.key.enc` |
| Remote S3 | `s3-secret-access-key.key.enc`; access-key ID and endpoints are non-secret config |
| Brevo | `brevo-smtp-api-key.key.enc` |
| GCP | `gcp-service-account.json.enc` |
| Grafana | `grafana-cloud-write-token.key.enc` |
| Judge0/admin/encryption | `judge0-auth-token.key.enc`, `admin-api-key.key.enc`, `encryption-key.key.enc` |
| AI pools | `openai-api-keys.key.enc`, `gemini-api-keys.key.enc`, `openrouter-api-keys.key.enc`, `anthropic-api-keys.key.enc`, optional `qwen7b.key.enc` |

## Run

For an opaque key:

```powershell
npm run secret:set -- dev/runtime/files/<fixed-name>.key
npm run sync
```

For a newline-separated AI pool, use multiline input and finish with `Ctrl+Z`, then Enter on Windows:

```powershell
npm run secret:set -- dev/runtime/files/openai-api-keys.key --multiline
npm run sync
```

For a Google service-account JSON held in a protected download:

```powershell
npm run secret:set -- dev/runtime/files/gcp-service-account.json --from-file <protected-json-path>
npm run sync
```

Configure non-secret endpoints, currencies, sender identity, OAuth client IDs, bucket/region and callback
URLs in the environment-specific encrypted app config. Never edit `config.ts` defaults to install one
environment.

Provider-side minimum setup:

| Provider | Configure before verify |
|---|---|
| Stripe/PayPal/PayOS/SePay/NOWPayments | sandbox app/account, exact HTTPS webhook, signing secret/IPN key, supported currency |
| Brevo | SMTP credential, verified sender/domain, from address/name |
| OpenAI/Gemini/OpenRouter/Anthropic | project key with minimum spend/scope; one key per line in the pool |
| DigitalOcean/S3 | bucket, region/endpoint, access-key ID, CORS/public-prefix policy |
| GCP service account | least-privilege role and only the APIs actually consumed |
| GitHub/data token | fine-grained repository access where supported; no organization-wide classic scope by default |

## Verify

Verify one safe provider operation before live traffic: sandbox payment intent, signed webhook fixture,
SMTP test message, AI ping, S3 put/get/delete under a test prefix, Google API read, or private-repository
metadata read. Then inspect application logs and the provider audit log; never print the credential.

```powershell
npm run secret:list
npm run sync
npm run lint:check
npm run test:unit
```

## Stop or rollback

Disable the integration through its non-secret feature/config switch where available. Restore the old
encrypted record before revoking it if the replacement fails. For payment webhooks, keep idempotency and
signature verification active during rollback.

## Rotate

Issue replacement → write the fixed encrypted record → publish deployed projection → restart consumer →
run one safe verification → revoke old value. Encryption keys are different: rotating
`encryption-key.key` requires a data re-encryption migration and cannot be treated as an API-token swap.

## Troubleshoot

| Symptom | First check |
|---|---|
| provider returns 401/403 | correct account/environment, scope and synced fixed filename |
| webhook signature fails | raw body, exact provider signing secret and correct endpoint environment |
| AI pool appears empty | filename matches the catalog and keys are newline-separated |
| SMTP authenticates but mail is rejected | verified sender/domain and from address |
| S3 upload works but public URL 403s | public endpoint, bucket policy and allowed prefix |
| GCP reports ADC missing | service-account JSON projection and least-privilege API enablement |

## Upstream

Use the current primary docs linked from each provider console. Reconfirm webhook and token scopes before
every production mutation; provider UIs and scope names are time-sensitive.
