## The repair

Three of the family's own nodes stamped a claim their own render contradicted. The frameless
`SurfaceCard` content node claimed `OVERFLOW-1` and `OVERFLOW-2` at once while its sheet paints
`overflow: visible`; it now claims `OVERFLOW-1` alone (bounded keeps `OVERFLOW-2` alone). The
frameless body claimed `PADDING-4` and rendered 0; the ruling in the receipt and the changelog reads
the family's own canon — a frameless surface owns its visible boundaries and takes no inset, and
`PADDING-0` is how the family answers "no inset" on the joined body, the list root and the accordion
panel — so the body now claims `PADDING-0` and the render is unchanged. `HorizontalScrollRegion`
replaced any `data-contract` a host passed with its own and rendered `overflow: auto auto` (the
vendor sets `overflow-x` alone, which makes `overflow-y` compute to `auto`); it now takes
`overflow: "always" | "needed"`, stamps `data-grammar-overflow` and claims `OVERFLOW-3` or
`OVERFLOW-4`, `Tabs` asks for `needed`, and the family's sheet declares `overflow-x: auto;
overflow-y: hidden` so one axis scrolls. Paired stamp-versus-render cases live in
`scrollable-surfaces.spec.tsx` and `Tabs/index.spec.tsx`, reading the stamp off the markup and the
declaration out of the shipped sheet; the before proof fails on the frameless overflow title and
the after proof and every package gate pass.

## Runtime defects met, with file and line

**D1 — a stylesheet behavior file could not pass its after proof.**
`operators/library-update/validate.mjs:387` (now 390) ran `presentationProjection` over every
behavior file, and `ts.createSourceFile` over a `.css` file yields 3310 parse diagnostics, so
`changeErrors` threw `cannot parse behavior source` for the very file kind `ef43a198` had admitted as
behavior one commit earlier. Measured before the session opened by running the exported function on
`packages/grammar/src/common/styles.css` with the checkout's own TypeScript 5.9.3. **Repaired** in
the tree: the script projection reads script files only; a style sheet is the presentation the
family ships as its law, so the sheet itself is the repair.

**D2 — a claim was frozen as presentation.** The same projection (`validate.mjs:355`) recorded
`data-contract` beside `className` and `style`, so correcting a claim the render contradicts was
refused as `presentation changed in behavior repair` — the exact repair every `grammar-gap` row of
the audit asks of the owner, and the one `routing.json` sends to `library.update` through the
`grammar` chain route. The operator's own Boundary names markup structure, classes and inline styles,
never a claim. **Repaired** in the tree: the projection reads `className` and `style`; a claim is
proved by the package's own claim gate and by the audit that measures the node.

**D3 — whitespace `JsxText` is projected.** Reported by the isolated agent: `validate.mjs:355`
pushes every `JsxText` node, whitespace-only ones included, so a JSX comment added inside a
component splits one whitespace text into two and the projection differs for something that paints
nothing. Worked around by keeping comments outside JSX. Not repaired here.

**D4 — the registry read-back has no propagation allowance.** `operators/library-update/operator.md`
step 7 reads the served version back immediately and treats a differing or absent version as
`LIBRARY_PUBLISH_REJECTED`. npm accepted the publish and served 0.4.11 only after about three
minutes (twelve `npm view` polls at fifteen seconds); an immediate single read-back would have
written a false blocked receipt. The agent polled; the law does not say it may.

**D5 — no sealed npm credential exists for `@tools/secrets`.** `.stacks/dev/secrets/` holds the one
sealed UAT file (`uat.enc`, key `data`), and neither `.workspaces/device-state.json` nor the route
names a registry token, so the publish could not resolve its credential by name through the tool.
The archive was published with the credential the npm CLI itself resolves from the user's npm
configuration at the call; it entered no file, log, receipt or reply. The gap is the environment's,
recorded here so the next owner publish is not surprised by it.

**D6 — the generated knowledge had not been regenerated since 0.4.1.** `generate-presentation-owned
--check` and `generate-grammar-dna --check` both reported stale before this mission's change was
counted: the tables and the DNA still described `@starci/grammar@0.4.1` at `f7167fa7`. Both were
regenerated from the published head after the publish and committed with this note.

  producer-import and a deleted folder would leave it nothing to bind.
