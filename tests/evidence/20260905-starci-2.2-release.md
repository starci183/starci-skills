## Result being verified

- Every prompt opens or reuses a host session before goal confirmation. Existing bootstraps receive
  a bounded entry block without replacing custom instructions. Unconfirmed versions cannot execute.
- Goal-derived workflows declare dependency and expected sources, then each attempt freezes its
  concrete expected criteria, environment and inputs before dispatch. Actual evidence is checked
  and sealed on acceptance; failure history remains available for owner repair and retry.
- Operator and helper execution share three worker slots and exclusive resource ownership. Source
  aliases, Windows junctions, case variants and parent/child resources cannot evade that ownership.
- Successful session close retains a compact and complete hashed proof bundle before removing only
  the active session. Active work, shared runtime registry, worktree and branch are preserved. The
  producer import protocol can read retained evidence and atomically publish a complete target copy.
- All 25 original operators and the helper have concrete EN/VI procedures. `knowledge.repair` is the
  26th operator. UAT has typed case sheets, actor/login proof, a separate seed/cleanup owner, frozen
  expected cases and actual assertions in append-only run history.
- UI work inventories all applicable knowledge files, rules and Cases, with Grammar mindset and
  source/version evidence. Canonical UI repair includes composition, presentation and proof, as well
  as the bound family. One candidate still renders and is scored. Valid tied candidates are selected
  deterministically within the approved goal.
- Imagery highlights ideas, explains content, supports recognition or creates a relevant visual or
  emotional focal point. It is judged for hierarchy, scale, contrast and crop; blank space alone is
  not a reason to add it. This clarification updates the family playbook and generation/audit flow.
- Reasoning/review use Sol/Fable and working roles use Sol/Opus. The bound and actual active profile
  are recorded and validated; historical profiles remain readable but cannot be assigned to new work.

## Defects found and repaired during integration

The baseline checkout failed the identity and runtime-serve self-tests because their fixtures did
not isolate the stack behavior they exercised. The procedure lane corrected those fixtures.
Integration then found and repaired these concrete failures:

| Finding | Repair and regression |
| --- | --- |
| Concurrent locks could contend during state updates or recreate a deleted session | Shared owner-aware lock and deleted-session waiter regression |
| A changed accepted response could otherwise invalidate retained proof silently | Exact request/response evidence seal and post-accept tamper rejection |
| Retention treated a local producer ref as an import, or accepted injected archive files | Local/import distinction, exact archive inventory and archive-junction rejection |
| Concurrent producer imports could leave a partial target | Locked source snapshot, isolated staging and one atomic target publication |
| Generated dispatch brief exceeded the existing byte cap | Removed duplicated job prose from the brief while retaining full Done when and authored procedures |
| UI self-tests assumed the repository root was their working directory | Resolve fixture knowledge from the module path; run tests from each operator directory |
| Common UI knowledge was omitted from a repair request | Expand the declared `@knowledge/ui` binding and test against the actual shipped Context table |
| Single-refine and image instructions contradicted the rendered-evidence gates | Align EN/VI instructions and the owner image clarification |
| UAT required inputs introduced unreachable planner transitions | Add the typed Next edges and retain all real chain fixture checks |
| Installed planner tests depended on files absent from the package | Move all 17 authoritative chain fixtures under the shipped scripts tree |
| Existing custom host instructions without a StarCi link bypassed the entry | Append the marked entry once on init/update; preserve existing bytes and --no-bootstrap |
| Actual execution profile was optional | Require and validate bound/actual profiles for v2.2 receipts |
| A draft mission could be planned as executable work | Confirmed lifecycle/version/choice gate and preview links to pending dispatch contracts |
| A consumer could read unaccepted same-session output bytes | Require a matched producer, its intact accepted evidence seal and the exact emitted kind/ref |
| Helper concurrency was only a prose requirement | Real helper request, atomic acquire-helper admission and common release share the operator cap and resource leases |

## Reach and limits

These checks prove the skill tree's contracts, routing, state transitions, filesystem effects,
adversarial refusals and package installation using controlled fixtures and subprocesses. They do
not claim that a live Academy frontend was redesigned or UAT-tested, that a real Grammar package
was published, or that credentials for every downstream product were exercised. Visual judgments
remain judgments grounded in rendered evidence; a schema cannot certify beauty by itself.

The successful-cleanup fixture includes a synthetic accepted receipt to exercise retention and exact
deletion boundaries; it is not a claim of a live readiness run. Other tests separately exercise
attempt and operator acceptance. Local `.worktrees/done` retention is not a cross-machine backup.

This release is a Git source update. No npm registry publication is included in the user's push
instruction, and an installed global skill copy is not implicitly updated by publishing this repo.
