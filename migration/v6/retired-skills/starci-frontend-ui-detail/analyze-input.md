# Analyze frontend UI-detail input

Require one approved UI direction, one approved UX flow, its approved interaction-container plan, page refs, Grammar package, and current generated frontend-context hash. Reject a handoff that omitted container selection or responsive transformation. Do not load raw source or implementation context. Enter fixed state `freeze`.

Bind the detail artifact to every surface and state in the approved flow. Treat `key` or `important`
pages as illustrative unless an explicitly approved partial boundary exists. If route pages versus
modal, panel or in-route state surfaces remain plausible and would change ownership, responsive rules
or baselines, return to global analysis for one focused clarification; never silently omit non-route
states.
