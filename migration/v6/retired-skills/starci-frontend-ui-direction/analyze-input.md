# Analyze frontend UI-direction input

Validate that the request needs visual ideation, the business authority, UX flow, and interaction-container
plan are fresh, the normalized target is exact, and three or four directions are requested. When the normalized `scopeUnit` is `branch`,
`journey` or `feature`, require a closed set of applicable surface roles rather than silently reducing the
work to the current page. Candidate roles are entry, core task, pending/recovery, result,
history/retry/resume and exit; omit roles that the approved business outcome does not need. Every
direction must render the important surfaces, relationships, reachable states, and responsive transformations in that closed set. Load only the approved UX/container refs; do not reopen journey decisions, load Grammar object detail, or load source files. Enter fixed state `generate`.
