## Contract addendum picked up (merge `main`)

- §4 `inputs` table added to `LEDGER_DDL` verbatim (markdown backticks stripped from its comment — they
  terminate a JS template literal).
- `inputs.put/get/list/materialise` implemented on the ledger handle so the store stream's §8 methods can
  delegate: `put` computes `sha256` over the bytes and returns `{ref:'ledger://inputs/<wf>/<key>#sha256=<hex>',sha256}`;
  `get`/`materialise` read through `readInput(db,{workflowId,key})` which recomputes the digest and throws
  `input-digest-mismatch` on drift (spec asserts both paths refuse). `list` returns metadata + `ref`.
- `retireWorkflow` now also drops `inputs` rows — required for the `workflows` FK on plain retire.
- Note for the store stream: `node:sqlite` returns BLOBs as `Uint8Array`, not `Buffer`.

## Readings I picked where the contract was ambiguous

- `appendEvent`/`enqueueJob` **auto-`ensureWorkflow`**: `events.workflow_id`/`jobs.workflow_id` are FK'd to
  `workflows`, and no 1.0.3 caller ever creates a workflows row first. Without this, every ported caller
  fails with a raw FK error. `ensureWorkflow` is also exported as a module function `(db,{...})` so it is
  callable inside a `transaction` body.
- `journalWorkflows` is ported under the name **`ledgerWorkflows`** and now also scans the `workflows`
  registry table (a registered workflow with no operational rows still shows).
- `retireWorkflow` keeps journal semantics but removes every `workflow_id`-keyed row (`goals`, `reports`,
  `contracts`, `checks`, `inbox`, `signals` by scope) and then the `workflows` row itself — required because
  the children FK-reference it. Under `preserveRuntimeCustody` the `workflows` row stays: the retained
  snapshot references it.
- `releaseTwoPhase(ledger,machine,{jobId,status,result})`: deletes lease rows, then with `status` settles
  the job (`status`+`result_json`, clears `lease_token`/`deadline`); without `status` it only clears fencing,
  mirroring `admission.release`. Machine `machine_ref`s are released after the ledger commit.
- `machine.release` accepts a token string or an array; `machine.reserve` accepts `ttlMs` (or `ttl` per the
  §6 pseudocode); `sweep({inspectLedger})` is injectable and skips ledgers whose file cannot be inspected
  (their TTL still owns the rows — fail closed).
- `runtimeRootFor` is duplicated one-line locally (same formula as `engine.mjs`) so `ledger-db.mjs` never
  imports the engine — engine will import this module, and a cycle on a `const` arrow is TDZ-fragile.

## Requests to other streams

- **Whoever ports `admission.mjs`**: `admission.reserve` currently inserts `leases` rows and only then sets
  `jobs.lease_token`. Under `leases_match_job` that order now aborts with `lease-identity-drift`. Set
  `lease_token` on the job first, then insert lease rows (the order `reserveTwoPhase` uses).
- `reserveTwoPhase` requires an existing job to be `queued` with matching identity (throws otherwise), or
  inserts it as `leased` when absent. Repo-scoped `leases` are capacity-checked against ledger `resources`
  counting only unexpired leases.
- The exact diff needed elsewhere: none — this stream needed no changes outside its owned files.
