# Composition evidence

## LOADS

| Alias | Target | Kind | Why |
|---|---|---|---|
| `@schema` | `knowledge/brainstorms/composition/schema.json` | file | validate the four-lock baseline and owner tree |
| `@validate-baseline` | `scripts/validate-design-baseline.mjs` | script | refuse incomplete scope, wrong parent and missing proof coverage |

## Record

This module runs before grammar or principles. It turns the request, screenshot, legacy page and current source into four locks: `Scope`, `Owner`, `Invariant` and `Proof`. It emits no class, component or visual treatment.

## Law

The reference is specification at the scope the owner named. A highlighted region proposes one parent containing every named or enclosed child until source evidence proves a nested owner. Current DOM is evidence, not a veto: when it wraps only part of the highlighted relationship, the parent is wrong and must be corrected before gap, flow, padding or alignment are resolved.

Legacy-backed content outside the target is preserved by default. An example proves only the situation it illustrates; it never promotes itself into a family invariant.

## Reading evidence

1. Lock one page or one explicit start-to-end flow.
2. Record every reference viewport and state.
3. Name the target owner, its direct children and any nested owners.
4. Bind screenshot annotations to owner/child identities; a coloured region must cover the same direct-child set the owner claims.
5. Separate preserved nodes from allowed deltas. The two sets never overlap.
6. State the invariant in semantic language, not literal example values.
7. Require full-viewport and target-region proof at every reference viewport/state.

## Rules

1. Grammar and principles cannot run while any of the four locks is unresolved.
2. A screenshot page never expands into another page; an explicit flow includes every named page.
3. A highlighted region defines parent evidence, not a decoration hint.
4. Legacy composition, hierarchy, visual owners and interaction remain unchanged outside allowed deltas.
5. A shared change requires measured consumers; a bounded annotation remains local.
6. Computed CSS is supporting proof, never full-viewport parity proof.

## Output

One `baseline.json` conforming to `@schema`, stored only in the current project design cache.
