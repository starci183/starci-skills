# Offset Pop case: simplify a dense operational screen

## Trigger

A screen contains many fields, rows, statuses, or operational controls and full Offset Pop expression would impair scanning.

## Decision

Keep personality at section headers, primary action, selected navigation, and one focal summary. Operational rows and fields use stable geometry, reduced shadow, minimal rotation, and consistent contours. Repeated status uses aligned neutral treatment, not stickers. Use spacing and alignment to establish hierarchy before adding color fields.

Apply an explicit accent budget: name which objects may receive strong fill, offset depth, rotation, and overlap. Everything else uses the quieter declared variants.

## Responsive

Reduce accents again, prioritize essential columns/actions, and use declared alternate layouts. Never hide consequence or state merely to preserve personality.

## Reject and proof

Reject maximum treatment on every object, color-per-row, rotated fields, animated repeated data, or decoration carrying state. Prove scan path, keyboard order, loading/error/partial states, zoom, and small screens.
