## Outcome loop

One audit mission optimizes for visible progress while preserving typed proof:

1. bind business facts, the complete direct feature owner group, central runtime generation, and one
   mission-scoped Browser/UAT lease;
2. capture a rapid representative baseline: wide, compact, core task, and worst recovery/constrained
   state; intermediate is required only when the breakpoint materially changes composition;
3. invoke executable `fe/baseline-visual-review` with one fresh Sol to obtain the routing score and
   complete initial finding batch; prose or implementer self-scoring cannot substitute for it;
4. route mechanically: `7-8 -> one batched repair`; `<7 + direct structural findings -> one dominant
   reconstruct`; shared/business/backend/runtime-auth findings route to their owner;
5. fix UX task flow and recovery before UI polish, construct the selected composition, then recapture
   only changed owners, adjacent sentinels, and affected interactions;
6. expand to the complete applicable Behavior/UX/UI matrix only for closure, update each owner
   `audit.md`, and leave the audited state visible for owner feedback.

Baseline evidence never certifies PASS. Closure still requires fresh typed PASS plus score at least 9.
Inapplicable probes require an exact owner/capability reason rather than synthetic exercise.
An absent bounded container therefore records all bounded-scroll phases as
`container-not-present`; it does not block capture and is not replaced by fake scrolling. Conversely,
an applicable recovery state remains required even when the Browser lacks request interception; the
central runtime owner must produce it safely or retain a typed closure gap.

The machine route for an audit is `ui-audit -> baseline-review`. A failed baseline continues through
owner classification and `audit-route`; a clean score-9 baseline remains SUSPENSE and expands through
capture preflight to the complete closure matrix. Non-audit create/repair/redesign/debug/reconcile
missions also render one dominant direction before Grammar binding when a dominant change exists.

## No-wait law

An audit-to-target request freezes reconstruct authority inside the approved direct owner group.
Below-7 structural failure generates and visualizes exactly one dominant direction, then constructs it
without asking the owner to choose. Three or four alternatives and a direction-choice WAIT exist only
when the owner explicitly requests comparison.

Routine runtime, quality, and UAT coordination is internal continuation. Report progress, but do not
end the task merely to narrate a routable next step. Shared-owner mutation remains permissioned: send
the exact request to Control Panel, continue all direct-owner work, and WAIT only when that shared
finding is the sole remaining closure gap.

## UI-only fast lane

When the owner explicitly freezes business behavior as already correct and asks for render-only or
UI/UX-only work, compile `delivery-mode=ui-only-preserve-business`. This is a preservation contract,
not permission to rediscover the product. The mission may change direct-owner composition, styling,
copy, accessibility, interaction feedback, responsive behavior, and navigation to an already
authority-backed route. It must not create or modify GraphQL operations, remote-mutation hooks,
backend contracts, auth/session behavior, fixtures, persistence, or a new route that introduces a
previously absent business action. A broken CTA does not authorize inventing its missing capability:
retarget or remove it using existing authority, or return the exact business gap.

Before the first write, freeze the exact allowed files and their hashes. After every write, compare
the actual tracked and untracked diff with that set. Any unlisted file or forbidden capability is
`mutation-boundary-drift`: stop the writer, remove only its task-owned drift with an explicit patch,
preserve unrelated work, and resume the direct UI batch from the last valid boundary. Static checks
cannot make a boundary-drifted batch valid.

## Observable writer continuity

One owner group has one source writer. A task badge or `active` status is not evidence that the writer
is progressing; liveness requires a recent observable tool event, validated receipt, or source change
owned by that task. On a silent writer, send one STOP/checkpoint request and do not start a second
writer. Ownership transfers only after the task is terminal, or after an explicit handoff plus two
read-only source checks showing a stable diff. If a late write lands after STOP, classify overlap,
halt both mutation paths, reconcile the exact diff, and then name one writer before continuing.

## Browser/UAT continuity

Feature tasks never handle raw credentials or mutate shared services. A centralized Browser/UAT lease
binds mission, account, isolated context, principal fingerprint, localhost origin, runtime generation,
fixture namespace, and expiry. Reuse it across audit/repair/recapture rounds. On contamination or
continuity loss, invalidate affected evidence and reacquire the lease; do not restart FE/API and do
not keep a temporary challenge across turns.

A read-only visual audit may acquire a new mission lease over an already authenticated UAT-pool
account/context when execution is sequential and the required role, locale, fixture visibility,
origin, runtime generation, and prior-lease release all match. Reset only browser-observable route,
scroll, locale, and open-overlay state before capture. The prior mission lease must be
released first. This reuse is forbidden for product UAT, flows that mutate user state, reset-sensitive
preconditions, role changes, or incompatible fixtures; those still require a fresh run-scoped account.
Session compatibility is proved once by the broker and never by asking the user to sign in again.
Do not inspect cookies, tokens, passwords, browser storage, or autofill to manufacture a clean-storage
attestation; those are prohibited inputs, not read-only reuse blockers.

Treat a cross-task tab interruption as a delivery failure, not identity loss. A symbolic handoff is
usable only after consumer-side discovery. Otherwise retain the authenticated lease, switch to
broker-executed capture, and continue from the same audit receipt instead of provisioning again.
