# Hierarchy follows user consequence

| Field | Value |
| --- | --- |
| Knowledge ID | `fe.ui.hierarchy` |
| Operators | frontend decision, implementation, review, and proof |
| Search tags | `hierarchy, reading order, action order, progress, fact rank, emphasis` |
| Dependencies | `fe.ui`; approved Behavior and UX authority; routed Grammar |

Reading order and action order must make the primary task unmistakable. Visual rank follows task
consequence and information weight, not decoration or convenient component defaults. Supporting
facts remain legible and subordinate; color is never the only carrier of order or state.

Every datum has an explicit presentation rank. A compact numeric fact or status remains subordinate
to its owning section and content title. Contract-declared progress remains an observable progress
presentation; replacing it with a badge is not equivalent. Contradictory metrics, redundant
emphasis, or secondary evidence that dominates the primary task are failures.
