# Every visible region has one owner and one purpose

| Field | Value |
| --- | --- |
| Knowledge ID | `fe.ui.ownership-composition` |
| Operators | frontend decision, implementation, review, and proof |
| Search tags | `owner, purpose, surface, nesting, disclosure, whitespace, dead zone` |
| Dependencies | `fe.ui`; `fe.layout-composition`; approved UX authority; routed Grammar |

Every meaningful region, surface, collection, boundary, and primary action has one perceptible owner.
A child surface is justified only by a distinct repeated schema, state boundary, interaction
boundary, or scan pattern; decoration alone never justifies nesting. Removing a child surface should
make ownership ambiguous, otherwise the nesting is unnecessary.

Preserve one dominant decision per primary surface. Separate subjects that have different decisions,
states, or scan patterns. Disclosure does not erase information load; it only defers it. If revealed
content overwhelms or creates a competing internal task, recompose it as a peer owner rather than
shrinking content until it fits. After splitting an overloaded owner, reselect the interaction
container from the remaining task instead of carrying the old container forward.

Whitespace is a relationship signal, not a quota. Large empty areas, stretched sparse support,
decorative shells, and blank scrollable terminal space require an understandable user purpose. Fix
wrong span, weak grouping, missing ownership, or missing approved content at its owner; do not hide
those defects with decoration.
