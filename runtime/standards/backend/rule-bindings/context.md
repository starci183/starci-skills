# Backend rule-binding accountability

## LOADS

None.

## Record

Rule bindings prove the chain from desired source shape to refusal to executable machine. Detailed law
remains in pattern and gate records; this module owns only accountability between identities.

## Chain

```text
pattern situation code
  → gate situation identity
  → published @starci/eslint-canon-be rule or external analyzer condition
  → executable proof
```

## Rules

1. An enforced gate without a published machine identity fails parity.
2. A published machine rule absent from the gate router fails parity.
3. Installed packages do not ship their test sources; machine-test proof remains `unmeasured external`
   until the canon source checkout or authorized upstream CI supplies evidence.
4. A documented-only situation is valid only when its law explains why a machine cannot decide it.
5. Pattern and gate codes remain stable; renumbering requires consumer migration evidence.
6. Consumer repositories install canon and never vendor a private rule copy.

## Stops

- Gate and package rule sets differ.
- A rule has no law owner.
- A plan claims an enforced situation whose binding is absent.
- External analysis evidence is required but unavailable.

## Proof

Run `node .claude/runtime/machines/rule-bindings/check.mjs --be` and the published canon test suite. Provider-side Sonar
conditions remain external evidence rather than inferred filesystem facts.

## Output

```text
pattern: <situation code>
gate: <gate identity>
machine: <published rule or analyzer condition>
proof: <executable evidence>
verdict: <bound | documented | missing | external>
```
