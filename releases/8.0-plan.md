# StarCi Skills 8.0 release plan

Status: draft for owner feedback; implementation and version bump are intentionally paused.

Date: 2026-09-02

## Evidence corpus

This plan synthesizes the complete visible histories of these two tasks:

- `thread://01a05c0a-103e-73e0-a283-373c0398e123` — 9 raw user turns.
- `thread://01a05e40-1bab-7d33-8df2-800d5e04a6ac` — 21 raw user turns.

The histories overlap, so raw turn count is not treated as 30 independent rules. Repeated observations
are deduplicated by contradicted claim, smallest owner, and missing proof. Product decisions remain in
product authority; only reusable observation, authority, routing, or proof failures enter runtime law.

## Release objective

V8 must prevent a mission from reporting a convincing local PASS while one of these remains unknown:

1. a business promise has unexamined enforcement consumers or lifecycle branches;
2. a page names a Grammar component but does not consume its visible anatomy, slots, and states;
3. a visual relationship passes by DOM/source intent while pixels attach it to the wrong owner;
4. an interaction, disclosure, responsive, overlay, route, or vocabulary state was never observed;
5. evidence belongs to an earlier source head or a different concurrent mission;
6. user counterevidence was repaired locally but its reusable process gap was not closed.

The release target is `8.0.0-beta.1`. This document does not authorize that bump. Version, schemas,
catalog, generated site, templates, and validators change only after the owner closes the open pattern
register below.

## What v7.6 already owns

V8 must extend, not duplicate, these current fail-closed laws:

- post-completion feedback invalidates the terminal verdict and requires the same-mission
  `ERROR -> RESUME -> fresh visual PASS -> Quality PASS -> UAT PASS` chain;
- a reusable counterevidence gap updates the smallest `.claude` authority and regression proof;
- foreign or concurrent source mutation makes evidence stale;
- a compile-time Grammar gap is repaired at Grammar authority, never with page-local imitation;
- unfamiliar business/interaction models require bounded reference research and cannot be filled by taste;
- interaction scope/state parity already covers rest, hover, `focus-visible`, active/pressed, selected,
  expanded, pending, disabled, and reduced motion;
- whole-page populated wide/intermediate/compact evidence, adversarial probes, fixed-edge clearance,
  visual ownership, and fresh blind review already veto technical green checks.

These rules stay. V8 adds the missing typed links that the subscription work exposed.

## Product decisions that must not become global runtime law

The following remain StarCi product/Grammar authority, not universal `.claude` rules:

- Pro price, monthly/yearly commercial terms, quota amounts, and legacy customer compensation;
- exact copy such as `Full access`, Breadcrumb labels, or benefit text;
- exact subscription-page spacing values such as `gap-6`, `pl-6 pr-4 py-3`, or later `pt-0` owner decisions;
- a universal ban on hover for every accordion or card;
- the specific illustration, page composition, and subscription route content.

V8 may require these decisions to be explicit, owned, observed, and proved. It must not choose their
values or copy one page's arrangement into a product-neutral rule.

## Planned v8 contracts

### 1. Feedback synthesis contract

Add one runtime-owned, closed synthesis artifact for releases and systematic counterevidence batches.
It records every source feedback reference exactly once with:

- direct observation and contradicted prior claim;
- disposition: `product-decision`, `reusable-gap`, `already-covered`, or `duplicate`;
- smallest owner and authority reference;
- missing check or false assumption;
- implementation and regression references for reusable gaps;
- canonical reference for duplicates;
- explicit non-generalization reason for product decisions.

The validator rejects unclassified feedback, duplicate counting, a global rule derived only from a page
preference, a reusable gap without regression proof, or an `already-covered` claim without an existing
rule and evidence that the rule was actually consumed.

### 2. Business promise-to-enforcement coverage

Extend business modeling with a content-addressed coverage matrix. For each approved promise it freezes:

- actor and eligibility;
- offer/read entry points;
- purchase and external-payment side effects;
- settlement/idempotency;
- entitlement and quota consumers;
- renewal, cancellation, expiry, denial, recovery, and refund behavior when applicable;
- legacy create/read/settle coexistence;
- enforcement owner, source reference, positive proof, and negative proof;
- explicit `preserve`, `replace`, `retire`, `defer`, or `not-applicable` disposition.

Business cannot publish `ready` while a discovered consumer or lifecycle branch lacks a disposition.
Backend implementation must return the same matrix fingerprint plus implemented consumer receipts.
Quality integration and UAT consume that exact fingerprint; UI copy such as “full access” cannot PASS
when the backend coverage matrix is partial.

### 3. Grammar anatomy consumption contract

Extend the compiled Grammar binding beyond package/export/component identity. Each rendered composition
must bind:

- visible owner and Grammar owner;
- frame, external label, header, body, media, secondary band, divider, action, and optional overlay slots;
- inset/full-bleed/flush/zero-footprint ownership;
- interaction hit-target scope;
- applicable rest, hover, focus-visible, active, selected, expanded, pending, disabled, error, and
  reduced-motion states;
- negative ownership boundaries that product CSS may not recreate or override.

The compiler emits `grammar-required` when the exact anatomy or state is absent. Source apply cannot
claim consumption from import name, DOM class, or visual resemblance. Grammar repairs require affected-
consumer regression before compile resumes.

### 4. Visual relationship contract

Freeze material relationships as first-class claims before mutation:

- label-to-surface;
- parent title-to-child description;
- section-to-section rhythm;
- media-to-frame full bleed;
- statement-to-secondary band;
- divider-to-owning band and adjacent gaps;
- CTA-to-action band;
- sticky/fixed/overlay-to-content clearance.

Blind review still judges pixels without producer rationale. The relationship manifest only defines
which claims require independent raster cells and prevents a producer from silently dropping them.

### 5. State and disclosure geometry proof

Add an executable disclosure rule:

- collapsed content contributes no unintended layout footprint;
- hidden panel, wrapper, body, divider, and transition owner are all measured/observed;
- expanded content receives inset only from the declared slot owner;
- rest, hover, focus-visible, pressed, expanded, and collapsed pixels are distinct where authority says
  they should be, and invariant where authority says they should not be;
- closed/open proof includes the neighboring rows and page rhythm, not a cropped body node.

This rule generalizes the missed HeroUI panel padding without hardcoding `16px` or one accordion library.

### 6. Canonical vocabulary and route contract

Compilation must bind approved canonical terms, locale keys, route spelling, and compatibility aliases.
A renamed concept records old route/API/catalog identities as `redirect`, `alias`, `retire`, `preserve`,
or `not-applicable`. Quality and UAT reject a route, visible label, GraphQL operation, or catalog term
that drifts from the frozen vocabulary unless its compatibility disposition is present.

### 7. Shell and shared-sentinel capture

Every compact and breakpoint-adjacent frontend packet must include the real persistent shell owners that
can occlude or squeeze the target: navigation, sticky/fixed controls, floating assistant, safe areas,
and overlay-open states. Hiding a shared overlay for capture is invalid unless the product flow itself
hides it. A repair recaptures the affected owner plus every dependency-linked shared sentinel.

### 8. Evidence graph hardening

Bind business coverage, backend implementation, FE compile, source apply, capture, blind review,
Quality, and UAT to one source/evidence graph. Any source mutation invalidates only the affected owner
partitions and dependency-linked sentinels, but no task may reuse a peer mission's PASS, an earlier page
head, or a stale Grammar package. Reuse requires an explicit dependency proof, not a verbal assertion.

## Planned machine integration

No new public mission Skill is planned. Existing owners receive stronger contracts:

1. `starci-business-process` authors and publishes the promise coverage matrix.
2. `starci-backend-process` consumes its fingerprint and returns consumer/lifecycle enforcement proof.
3. `starci-fe-process` consumes approved business coverage, vocabulary, Grammar anatomy, visual
   relationships, and interaction-state matrices during `fe/request-compile`.
4. `fe/capture-preflight` rejects missing disclosure cells, shell sentinels, route identity, owner
   relationships, or stale source/Grammar binding before raster capture.
5. `fe/visual-fidelity` remains raster-only and receives no producer rationale; the packet shape ensures
   required states and neighboring owners are present.
6. `starci-quality-assure` stays verification-only after FE visual PASS and checks that every upstream
   fingerprint and required rule result is preserved unchanged.
7. `starci-uat-verify` proves the actor-facing decision flow and backend-owned business outcome from the
   same matrix, including negative and recovery branches that are product decisions.

Prefer extending current operators and validators. Add an atomic operator only if one job cannot be
expressed without mixing authority, mutation, or proof boundaries.

## Planned regression suite

V8 is not releasable from prose alone. Add fixtures derived from the observed failure classes:

1. reject “full access” when one entitlement consumer is absent from the coverage matrix;
2. reject stopping legacy sales while an old create or pending-settlement path is unclassified;
3. reject a Grammar import whose external label/frame/body slots do not match the bound anatomy;
4. reject a closed disclosure whose hidden wrapper still contributes layout height;
5. reject full-bleed media with product-local inset and reject a divider attached to the wrong band;
6. reject parent/child typography that passes class checks but renders the wrong visual hierarchy;
7. reject hover-only feedback, leaked card hover, missing focus-visible parity, and selected/expanded
   state conflated with active;
8. reject compact evidence that hides or omits a persistent floating shell owner;
9. reject misspelled canonical route/term without an approved alias disposition;
10. reject a PASS borrowed from another task or captured before a later source/Grammar mutation;
11. reject a feedback synthesis that globalizes `pt-0`, `Full access`, or another page-specific choice;
12. accept the complete correlated business -> backend -> FE -> visual -> Quality -> UAT chain once and
    reject replay.

Focused tests precede full `npm test`, materialization, site generation, release validation, and a clean
rerun from the published v8 source head.

## Migration and compatibility plan

Proposed, pending owner confirmation:

- bump runtime and public contract version to `8.0.0-beta.1`;
- bump typed mission/operator envelope `schemaVersion` to 8 because required fields and terminal
  predicates change materially;
- publish a matching Grammar contract version only after anatomy/state manifests exist; do not claim
  `grammarContractVersion: 8.0.0` against an unpublished Grammar package;
- reject direct resume from v7 receipts; allow one explicit read-only migration that rebinds current
  source heads and recompiles authority rather than translating PASS;
- preserve historical v7 evidence immutably as legacy evidence; it cannot close a v8 mission;
- regenerate package locks, Skill catalog, Sites catalog, schemas, templates, and release checks from
  the same version bump;
- retain the 13 public mission Skills unless a later owner-approved pattern proves a new durable owner.

## Implementation sequence after plan approval

1. Freeze this feedback synthesis and the new-pattern register.
2. Implement feedback and business-impact schemas/validators with adversarial fixtures.
3. Extend business/backend/Quality receipts and correlated fingerprint chain.
4. Extend FE Grammar anatomy, relationship, vocabulary, state, and shell-sentinel contracts.
5. Extend capture and visual/quality/UAT terminal predicates.
6. Run focused regressions; repair the smallest runtime owner only.
7. Perform schema/version migration and materialize generated artifacts.
8. Run the full release suite twice from a clean source head.
9. Publish changelog only after all v8 terminal predicates pass.

## V8 acceptance criteria

V8 may be reported ready only when:

- every feedback item in the frozen corpus has exactly one validated disposition;
- every reusable gap has a failing fixture before its fix and a passing regression after it;
- no product-specific subscription decision appears as product-neutral runtime law;
- business promise coverage is correlated through backend, FE claims, Quality, and UAT;
- Grammar consumption is proved by anatomy/slot/state ownership, not component naming;
- compact/shared-overlay, disclosure, interaction, vocabulary, and evidence-freshness fixtures fail closed;
- all versioned schemas, templates, catalog artifacts, materialization, and release validation agree;
- complete `npm test` passes twice from the same clean published source head;
- an independent fresh review finds no unclassified feedback or bypass path.
