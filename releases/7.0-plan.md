# StarCi Skills 7.0 release plan

Date: 2026-08-29

## Evidence

- Dashboard UAT proved that a mechanical loading/empty/error/refresh list overstates product coverage; the minimal closed set was the authenticated landing-and-tabs journey plus the anonymous session boundary.
- The happy Dashboard run proved Behavior while UX failed because the full-width identity rail pushed the main task below the viewport. Missing UI detail left a finite UI question, but it did not invalidate the Behavior evidence.
- The same run exposed two process defects: unrelated `miamia` readiness initially blocked the exact StarCi Academy route, and a predictable email-length mismatch created a partial external identity before database rejection.
- User direction required account publication before execution, sequential visible Browser work, evidence captured inside the journey, independent Behavior/UX/UI verdicts, and UI evaluation against both Grammar and approved UI authority.

## Release boundary

7.0 first replaces the operator transport contract, then changes UAT selection and execution semantics without adding a new lifecycle skill:

1. Make every operator one straight-line job with the public contract `operator(context, input) -> output`.
2. Remove routing, state, facts, cleanup and next-step ownership from operators; Skill machines own branching and runtime owns session context/cleanup.
3. Require closed, semantically described direct fields and validate embedded artifacts against their declared schema.
4. Remove Qdrant, embeddings, generated knowledge packets and `knowledgeRefs`; resolve exact context with the agent's default repository/file search.

5. Compile product-level decision branches and delegate component-local permutations with exact proof.
6. Predeclare every case and execute visible Browser cases sequentially.
7. Preflight fixture constraints, then permit meaningful run-namespaced render seeds before execute.
8. Freeze journey evidence once; Behavior, UX and UI consume it independently.
9. Aggregate UI from separate `fe.ui` and Grammar verdicts; either failure is an aggregate failure.
10. Bind readiness blockers to the exact routed project.

## Migration

- Qdrant removal is complete: the two Python indexing runtimes, query/setup scripts, `starci-source-index-publish`, and its four platform operators are retired. The active catalog now contains 50 skills and 124 operators; canonical Markdown and clean reference checkouts resolve through default search.
- All 124 active operators now pass the strict v7 contract. Every operator declares one job, accepts only a closed `context + input` envelope, and emits one closed atomic `output` without owning routing, workflow state, or runtime cleanup.
- Every Skill-machine operator edge now consumes `outputEquals.outcome`; the durable migration check rejects legacy `decision`, `stage`, and `status` routing on strict-v7 operators.
- Runtime Source topology is frozen as `.claude/.workspaces` for verified project-role routes. Each routed project backend Source owns flat `.worktrees/businesses`, `.worktrees/uat`, `.worktrees/debts`, and `.worktrees/coding-context` roots with no project-name layer below `.worktrees`.
- Operator field documentation and flat backend-authority paths have idempotent migration checks. Hand-authored operator and Skill contracts are preserved by materialization so legacy generators cannot overwrite v7 contracts.
- Remove the Qdrant runtime, dependency, query scripts, operator knowledge bindings and Qdrant-specific platform capability. Preserve the durable Markdown authority and resolve it with default file search.
- Migrate `.uat/reviews/**/feature.json`, `review.json`, and `runs/**/result.json` from schema version 1 to 2 before validating them with 7.0.
- Add contiguous `executionOrder`, declaration/precondition/expected-outcome receipts, fixture constraint-preflight and render-seed receipts, plus separate UI-authority verdicts.
- Historical immutable run evidence is not rewritten. A v2 review may reference it as legacy evidence, but final 7.0 acceptance requires a fresh v2 run.

## Proof

- `node operators/contract-v7.mjs operators --strict` reports 124/124 active operators ready.
- Materialization preserves 124 hand-authored operators, four strict-v7 UAT audits, and 50 hand-authored Skill machines without regenerating legacy envelopes.
- Operator regression passes 51/51; UAT protocol passes 21/21 and rejects undeclared/non-contiguous cases, manufactured fixture success, and Grammar failures disguised as SUSPENSE.
- Operator harness passes 496 cases with zero failures; Skill harness reports zero hard failures.
- Full `npm test`, release validation, and the Skills site regression/build pass. V7 has no Python search-runtime gate.
