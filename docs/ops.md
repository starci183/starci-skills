# Ops — writing an operation contract

An **op** is the unit of work the kernel dispatches to one ephemeral `[Op]`
agent. Every op is an authored YAML manifest at `modules/ops/ops/<id>.yaml` —
data, not code. The kernel never reads a whole manifest to route: routing
reads only the `route:` block; the rest is the brief the dispatched agent
executes under.

The full authored vocabulary is exercised by the 31 shipped manifests; this
page is the anatomy, using `backend.implement` as the example.

## Anatomy of `modules/ops/ops/<op>.yaml`

```yaml
id: backend.implement            # unique op id — the file name must match
goal: {en: "…"}                  # one sentence: what done means
nodeKinds: [implementation]      # which .starciwork node kinds may carry it
completionProfile: implementation
sideEffects: [...]               # honest list: source edits, scoped commits, …

graphPolicy:                     # how the op may touch the record graph
  mode: read-only                # it reads node records; it does not reshape them
  prerequisiteState: done        # declared prerequisites must be effectively done
  dispatch: never                # an op never spawns further work itself

reads:                           # the CLOSED read set — what the packet may hand it
  - id: architecture
    path: .starciwork/<business>/architecture/**/index.yaml
    purpose: {en: "…why this read exists and its limits…"}
  - id: repo
    path: repository:<repo-id>/<bound-paths>
    purpose: {en: "…"}

writes:                          # the CLOSED write set — enforced at settle
  - id: source
    path: repository:<repo-id>/<write-ceiling>
    fields: [source files, tests]
    content: {en: "…what a legitimate write looks like…"}
  - id: evidence
    path: E/manifest.yaml + E/tests.json + E/result.md
    fields: [id, nodeId, inputDigest, outcome, assertions, assets]
    content: {en: "…"}

proofs:                          # the verdict must stand on these
  - id: behavior
    requirement: {en: "Scoped unit tests and backend E2E tests both pass …"}

blockers:                        # typed escape hatches, not free text
  - code: SCOPE_WIDENING
    condition: {en: "Required operation lies outside selected code-scope."}

commitPolicy:                    # may it commit? how verified?
  mode: scoped-local-commit
  verify: git-readback-full-sha-and-diff
  push: false

qualityPolicy:                   # the checks `settle` re-runs before `pass`
  checks: [lint, typecheck, unit, backend-e2e, coverage, build, sonar]
  requiredResult: pass
  missingRunner: blocked         # a gate that cannot run is blocked, never skipped

route:                           # the resolver index — route-op.mjs reads ONLY this
  nodeKinds: [implementation]
  phase: [implement, implementation]
  intent: [implement, backend, code, api, build]
  prerequisites: ["business.decide settled pass (reviewed SRS seed; Work leaves remain todo)", "architecture.decide settled pass (reviewed SDS seed; Work leaves remain todo)"]
  riskHints: [source-edits]
```

### Field rules

- **`reads`/`writes` are closed sets.** Anything not declared is out of scope;
  a `settle` whose report names files outside `owned_paths` is refused
  (`out-of-scope-files`). A kind with no writes declares `readOnly` semantics
  via an empty `writes` list.
- **`proofs` + `qualityPolicy.checks` are the acceptance.** `pass` is recorded
  only after the declared checks re-ran green on bytes computed from git —
  never on the agent's say-so (`modules/kernel/verdict-contract.yaml`).
- **`blockers` are the only legal way to stop.** An op that hits an undeclared
  wall reports the closest declared blocker or `failed` — it never invents a
  new outcome or quietly expands scope.
- **`route:` is denormalized for the router.** `scripts/route/route-op.mjs`
  matches on `route` alone; keep it consistent with `nodeKinds` and the
  registry (`modules/ops/registry.yaml`, generated by
  `node scripts/route/build-ops-registry.mjs` — regenerate, never hand-edit;
  see [ops-source-ownership](ops-source-ownership.md)).
- **`business:`** is analysis metadata (question, whenNeeded/whenNot,
  consumes/produces, failureModes) — informative, not enforced.
- **`placeholders:`** names the `<tokens>` used in paths above.

## Lifecycle of an op

```text
kernel: api enqueue --op <id> --paths <csv>   (brief file must exist → unknown-op)
      → api dispatch --job <id> --spawn      (packet = {op, brief, context, constraints, returns})
      → [Op] agent works inside owned_paths, files its report row
      → api report --job <id> --report <file>  (starci/op-report@1 envelope)
      → api consume-report → api check → api settle --job <id> --verdict <v>
```

The packet fields and lease semantics are `modules/kernel/dispatch.yaml`; what
`settle` accepts is `modules/kernel/verdict-contract.yaml`; the tick that calls
them is `modules/kernel/driver-loop.yaml` ([workflow-kernel](workflow-kernel.md)).

## Checklist for a new op

1. Pick a unique `<family>.<verb>` id; create `modules/ops/ops/<id>.yaml`.
2. Declare `goal`, `nodeKinds`, `completionProfile`, honest `sideEffects`.
3. Enumerate `reads`/`writes` minimally — the write set becomes `owned_paths`.
4. Write `proofs` + `qualityPolicy.checks` that actually prove the goal.
5. Declare every legitimate stop as a `blockers` entry.
6. Fill `route:` so route-op resolves it; run
   `node scripts/route/build-ops-registry.mjs` to regenerate the registry and
   `--check` to verify.
7. Dry-run: `node scripts/kernel/api.mjs dispatch --job <id>` (no `--spawn`)
   prints the packet without reserving or launching.
