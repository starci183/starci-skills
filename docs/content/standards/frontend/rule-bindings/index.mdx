# Frontend rule-binding accountability

## LOADS

None.

## Record

This module proves that frontend pattern situations, gate routes and the published
`@starci/eslint-canon-fe` machine remain accountable to one another. It owns identities and parity,
not duplicated design or gate law.

## Rules

1. Every published frontend rule appears exactly once in the frontend gate router.
2. Every routed rule resolves to an existing gate runtime record.
3. Shared or machine-only identities are stated explicitly rather than assigned a false pattern code;
   upstream machine-test proof remains external when the installed package omits tests.
4. Consumer repositories import the published package; a manifest dependency without a config import is absent adoption.
5. Source-level disable directives never substitute for a missing binding.

## Proof

Run `node runtime/machines/rule-bindings/check.mjs --fe` and the canon package test suite.

## Output

```text
rule: <published identity>
situations: <pattern codes or machine-only identity>
gate: <runtime record>
owner: <published law owner>
verdict: <bound | missing>
```
