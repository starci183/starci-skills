# Import graph constraints

## R26 tier direction {#r26}

`BE_TIER_DIRECTION` and `FE_TIER_DIRECTION` reject imports against the owner tier matrix, including type-only imports and re-exports. Features may depend on the lower tiers their slot permits; a domain owner cannot import a feature. On the front end, page and layout owners may import overlay entries, while other feature-to-feature edges and component-to-overlay edges are forbidden. `ARCH_PACKAGE_IMPORTS_APP` rejects a shared package importing an app, even through a type-only re-export. Move the shared contract into a package and have the app import it.

## R27 owner cycles {#r27}

`ARCH_OWNER_CYCLE` rejects a cycle between distinct owners in app and runtime graphs. A type-only import still contributes an edge. Keep dependencies one-way by moving a shared contract to a lower owner or replacing a cross-owner call with the appropriate event boundary. The finding identifies the owner cycle and its import edges.

## R28 feature isolation {#r28}

`BE_FEATURE_IMPORTS_FEATURE` rejects an import from one back-end feature owner to another feature of the same trigger kind, whether the edge imports a runtime value or a type. A feature can instead import a domain, platform or integration capability permitted by its tier. Features of different trigger kinds are separately rejected by `BE_KIND_ISOLATION` and communicate through domain events.
