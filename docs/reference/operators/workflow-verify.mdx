## Job

Verify one coordinator's frozen peer portfolio from the original terminal solo session receipts and
evidence, independently proving every child goal and pinning every delivered repository boundary,
without changing any peer session, worktree, source or ledger.

## Done when

Done when the `workflow-verification-report` maps every frozen coordinator done-when line to its assigned peer, proves each peer completed every line of the exact frozen child goal, binds each routed repository's full delivered head to accepted delivery evidence and its exact current Git HEAD, keeps earlier source-bound goal evidence only when its revision is an ancestor in that same repository, and preserves rereadable state and branch fingerprints for every claim.

## Messages locate proof, never become proof

The coordinator may use ordinary two-way task messages to assign work, receive a session id, report
status, return feedback and choose when to look again. Those messages are transport only: they grant
nothing, route no operator step and prove no outcome. Before this operator runs, the coordinator
freezes the received identities and exact child mission goals in `request/peers.json`; this operator reads that file and the
original peer evidence, and imports no peer receipt.

The coordinator does not impersonate this operator's bound profile. The orchestrator dispatches one
isolated `sol-reviewer` worker, with no inherited task transcript, inside the coordinator's existing
StarCi session. That worker opens no native task or user workflow: its request, attempt, receipt,
lease and worker slot remain in the coordinator's same chain, ledger and shared slot budget. The
coordinator still owns decomposition, messages, waiting, feedback and the final portfolio conclusion;
the isolated worker owns only this read-only verification attempt and records the profile that really
ran it.

Before dispatch, the caller must expand the frozen peer inventory into the request's Context list.
For every peer it names at least one concrete original evidence alias —
`@worktrees/sessions/<sessionId>` while live, `@worktrees/done/<sessionId>` after close-success, or
both through normal retention — with the same session id found in `request/peers.json`. Only those
explicitly bound locations may be read. A bare sessions or done root, a sibling scan, an alias not
present in the frozen inventory, and discovery from message prose are all forbidden.

Each peer remains the sole owner of its own solo workflow, session ledger and worktree. A peer counts
only when its original session is terminally successful, has no unfinished attempt, blocker, worker
or lease, has the same mission goal frozen for it, and passes the session and response gates from its
own bytes. For a version 2 snapshot, every original done-when line is proved independently. A
source-bound proof must resolve in the repository named by its routed workspace alias and be an
ancestor of that repository's delivered head. Each delivered head must also have the snapshot's
named original child done-when evidence accepted at that exact revision, resolve as a commit in that
same repository, and equal the proving worktree's current HEAD. Version 1 keeps the original
single-head equality law and host-bound worktree fallback for already frozen one-repository peers.
A context head mention alone never binds a peer. Version 2 may resolve a context-only binding only
from validator-accepted proof that unambiguously maps that alias to one Git repository. A live
session is read where it stands; an
explicitly closed session is read only after its retained bundle passes the normal retention check.

The coordinated topology's `ancestralEvidenceOperators` is the one closed exception list. For every
other original done-when producer, every routed workspace alias in its accepted proof is a required
exact-head obligation. `deliveryDoneWhen` records that derived obligation; it cannot omit or weaken
one. An accepted proof carrying both frontend and backend contexts therefore binds both boundaries,
even when the two repositories happen to contain a commit with the same object id. One accepted
proving row must simultaneously match every routed repository head for that done-when; rows from
different runs cannot be combined into a repository-head tuple that was never observed.

Missing, changing or rejected peer evidence produces no partial report. The coordinated session may
keep waiting, send feedback to the owning peer, and enter a new local verifier attempt under the same
authorized goal when evidence changes; this operator never edits the peer to manufacture that delta.

## The best outcome

On `done`, `response/data/workflow-verification-report.json` is the whole portfolio proof: its peer
set, exact child goals, ownership and repository heads equal the frozen coordinator snapshot; every coordinator done-when line is
owned; and every peer row names the original solo session state hash, each original goal proof, plus exact delivered-head evidence
fingerprints. It contains no message transcript, copied receipt, inferred success or partial verdict.
