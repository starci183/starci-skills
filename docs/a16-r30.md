# R30 public owner surface

In lite and full, each owner exposes one root `index.ts` containing explicit named reexports. Cross-owner imports use that entry; imports within the owner stay relative and address the declaring file. `BE_PUBLIC_SURFACE` rejects deep aliases, self aliases, relative escapes, folder specifiers, nested indexes, declarations in an index and export counts above the owner budget: 60 for domain and feature owners, 80 for integration entries.

`ARCH_OWNER_EXPORT_BYPASS` rejects importing another owner's private file. `ARCH_OWNER_EXPORT_STAR` rejects an entry that uses `export *`. The same owner boundaries apply to the back end and front end.

`HFS_ALIAS_REEXPORT` preserves a declaration's name: use `export { Original } from './original'`. Renaming it through `export { Original as Other }`, `export const Other = Original`, `export type Other = Original` or an empty `export interface Other extends Original {}` is refused.

`ARCH_PACKAGE_EXPORT_BYPASS` requires a cross-package import to use the package name and a subpath listed in its `package.json` exports. Importing `@fixture/ui/public` is valid when `./public` is declared; importing an undeclared private subpath is refused.

The edition-specific RuleTester witnesses in `packages/eslint/be/a16-r30-public-surface.spec.mjs` exercise every R30 lint enforcer with valid and invalid cases, including both graph plugins. Both managed identity owner templates demonstrate the explicit named-entry form.
