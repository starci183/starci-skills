# Back-end composition and schema ownership

## R32 app composition only

`BE_APP_COMPOSITION_ONLY` keeps each application's source to its declared bootstrap, app module, environment reader, options and composition group roles. Put pricing functions and other business work in the owning feature or module. `BE_APP_BUSINESS_ROLE` reports a business or provider role, such as a service class, under an application's source. Both editions apply the same boundary.

## R33 entrypoint ownership

`BE_ENTRYPOINT_ONLY_IN_APPS` reports `NestFactory.create*` calls and top-level `bootstrap()` calls outside an application's `main.ts`. The declared TestWorld slot is also a composition root and may boot the real apps. Features, ordinary test fixtures, environment files and other app files delegate process startup to these owners in both editions.

## R34 schema authority

`BE_SCHEMA_AUTHORITY` keeps application schema changes in owned migrations. TypeORM connections declare literal `synchronize: false`, omit `migrationsRun`, and use explicit entity and migration arrays. Run migrations through the CLI migration feature or TestWorld. Runtime services cannot synchronize schema, run migrations, seed at boot or execute DDL. TestWorld's verified private connection may provision its generated write-fault infrastructure while preserving production constraints and existing triggers and holding its operation lock until catalog-confirmed cleanup. These requirements apply in both editions.

## R35 schema ownership

`BE_SCHEMA_OWNER` places entity classes in their domain or platform capability's `persistence/entities/` and migrations in `persistence/migrations/`. The capability exports its named entity and migration arrays through its public index; apps register those arrays on one declared connection and the capability injects that connection's entity manager. Only manifest-declared per-connection platform capabilities may register on multiple connections. Migrations use a 13-digit epoch filename, matching class and `name`, and are proven through the app's migration-backed e2e world. Both editions use the same ownership rule.
