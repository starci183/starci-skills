## Correct self-upgrade flow

```text
active request
  -> prove the requested object is the StarCi runtime
  -> freeze fixtures, acceptance, metrics, diagnostic layers, and retry policy
  -> check the actual output before producer rationale
  -> if PASS: rerun once from fresh evidence; require two consecutive passes
  -> if FAIL/unstable: audit objective/scope, input, prompt, state machine,
     execute logic, knowledge, Grammar/UI when applicable, validation,
     output contract, tool/model boundary, and proof
  -> identify the smallest runtime owner and record ADD / CHANGE / REMOVE
  -> if calibrate: record diagnosis and BLOCK; it has no repair authority
  -> if upgrade: repair one approved .claude owner and rerun unchanged acceptance
  -> retry at most three repairs; stop immediately on repeated fingerprint
  -> COMPLETE only after two fresh consecutive correct outputs plus delivery proof
```

The flow must never silently switch from calibration to product delivery. Product mutation requires a
separate explicit mission and scope. Correct transitions with a wrong or unstable output are a failed
mission.
