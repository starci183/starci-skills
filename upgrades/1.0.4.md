# Upgrading an installed runtime to 1.0.4

This page is for the person who operates an installed runtime — the `.claude` directory of a host — rather
than for someone reading the source. It says what changed under you, what you have to run once, and what is
safe to leave alone.

`starci update --dir <host>` moves the payload, rebuilds and verifies `.dist`, and records the new version.
Everything below is what that update does **not** do for you.

## Do this once, per repository that owns a Work tree

**Import your workflows into the ledger.** A workflow's record used to be a directory of files under
`.starciwork/_local/workflows/<id>/` — `state.json`, `events.jsonl`, `kernel.lock`, `stop.flag`, the reports,
the contracts, the checks, the inbox — beside a global `journal.sqlite`. In 1.0.4 the record is one SQLite
file per Work root, `.starciwork/runtime.sqlite`, and the kernel neither writes nor reads `_local` any more.
It does not guess: a kernel that finds a `_local` workflow directory with no matching ledger row stops with
`ledger-unmigrated` rather than starting that workflow again from nothing.

```
node <host>/.claude/bin/starci.mjs ledger-migrate --repo <the repository that owns .starciwork> --dry-run
node <host>/.claude/bin/starci.mjs ledger-migrate --repo <the repository that owns .starciwork>
```

Run it once per Work root, not once per workflow. Nothing is deleted: the import records every source it
read and a second run skips them, the old directories stay where they are, and `journal.sqlite` is left in
place read-only for audit. Pass `--archive true` if you want the imported directories moved aside to
`_local/workflows-archive/<id>.migrated`.

The migrator refuses, and writes nothing, while a kernel lock for a workflow is held by a live process, or
when the old journal holds an unsettled job whose workflow state has already moved past it — that second one
is a reconcile for the kernel, not for the importer. **Stop the supervisor and the kernels first**, migrate,
then start the supervisor again.

**Commit the anchor.** `.starciwork/runtime.sqlite` is untracked, so a fresh clone of your repository starts
with no ledger at all. What travels with the repository is `.starciwork/ledger-anchor.json`: a small tracked
file holding, per workflow, the head of the event chain and the generation it was last checkpointed at. It is
written inside the same call that commits a checkpoint, and it is the counter-record that turns a lost or
rolled-back ledger into a refusal instead of a silent restart at generation zero. Commit it with the Work it
describes. `starci ledger-anchor --write --repo <root>` regenerates it from a healthy ledger.

## What changed under you

**One file is the record.** State, events, jobs, leases, goals, reports, contracts, checks, the inbox,
signals, loads and budgets are tables of `.starciwork/runtime.sqlite`, committed together. A state snapshot,
its audit event and its job or lease change are now one transaction, so a lease that names a job that does not
exist, a writer reservation with no owner, and a pending job nobody reconciled stop being things to detect —
they cannot be written. Archiving a workflow is copying one file; inspecting one is a `SELECT`.

**Only provider quota is machine-wide.** `%LOCALAPPDATA%/StarCi/runtime/machine.sqlite` keeps `ai/*` provider
quota and the machine budgets, because those span repositories. Nothing else lives there.

**Verbs renamed with the thing they act on.** `journal-prune` and `journal-retire` are `ledger-prune` and
`ledger-retire`, and they take `--repo <root>` instead of `--journal-file`. The old names are refused with a
pointer to the new one rather than quietly reinterpreting your flags. New beside them: `ledger-verify` (walk
the hash chain, and check the ledger against its anchor), `ledger-anchor`, `ledger-migrate`, and
`workflow-export --id <id> --to <dir>`, which writes the old human-readable file layout **out of** the ledger
whenever you want files to read. Export is a copy; it is never the record.

**A worker asks the CLI for its contract.** Workers no longer read files under `.starciwork`. An operation's
contract is `starci op-contract --workflow <id> --op <op> [--attempt N] [--dispatch <id>]`, which prints the
markdown (or `--json true` for markdown and context), and hands a dispatch nobody else's contract. The ledger
file is outside every operation's write allowlist; the allowlist compiler refuses an operation whose scope
would cover `.starciwork/runtime.sqlite*` with `scope-covers-ledger`.

**The runtime is not a Work root.** The Work root used to be resolved with `git rev-parse`, and the runtime
is its own git checkout — so any command whose working directory sat inside `.claude` resolved the runtime as
its own Work root and opened a second ledger there. One was found holding a live workflow's id. A parallel
record is worse than no record, so this is refused by name now: `ledger-root-is-runtime`, with the same
answer it always had — route the project through `.workspaces`.

## What is safe, and stays as it is

**Your product records.** Nothing under `.work`, `.worktrees` or your source tree is touched by this update.

**Your old files.** The migrator copies; it does not move or delete. `_local/workflows/<id>/` and
`journal.sqlite` stay exactly where they are, and remain readable, after the import.

**An approved, unfinished workflow.** Once migrated it resumes at its own checkpoint with the same
generation, the same counters and the same operations. An operation that was in flight when the kernel died
is reconciled at the next start, as it always was.

## If something looks wrong

`starci ledger-verify --repo <root>` is the first thing to run: it walks the hash chain of every workflow and
checks each against the tracked anchor. Three answers name a real thing rather than a corrupted file:
`ledger-chain-broken` (an event row was rewritten or removed under the runtime), `ledger-behind-anchor` (the
ledger does not carry the head the anchor records — a restored, rolled-back or rewritten file; the named
recovery is a backup or `ledger-migrate`, never a fresh start), and `ledger-identity-mismatch` (a different
ledger was dropped into a checkout that already carried a history). `ledger-missing` is the re-clone case:
the anchor travelled with the repository and the ledger did not.

Then run `starci doctor --dir <host>`, which runs the installed copy's own contract tests and reports local
drift.
