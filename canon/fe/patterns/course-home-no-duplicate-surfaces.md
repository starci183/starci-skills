# A course home does not repeat a surface that already has its own page or sidebar entry — STRICT

> Read from a course-home design that proposed a grid of launch cards, one per surface, and lifted
> the learner's leaderboard rank onto the home page.

## The Learn sidebar is already the directory

The Learn area's sidebar navigates to every surface: mind-map, modules, foundations, flashcards,
practice, personal-project, leaderboard. A grid of launch cards on the home page pointing back at
those same surfaces is the same navigation offered twice, and it costs the reader a scan to discover
it leads nowhere new. A home page is not an app drawer.

## Every piece of data has exactly one home

Information that already has its own page — `rank`, which belongs to the Leaderboard — is not
duplicated as a fragment on the course home. Two copies drift, and the reader has to learn which one
is authoritative. The home keeps only what the home is the home of.

## What the course home is actually for

Three things, and they are the three that have nowhere else to live:

- **Continue** — the resume pointer, as the single primary action.
- **Overall progress** for the course.
- **The "where am I" path** — the current module and the next lesson.

Anything with a surface or page of its own is reached through the sidebar instead.

## The test for keeping a block on the home

Keep it only if it is either (1) work the home itself must do — continue, progress, path — or (2) a
**time-sensitive nudge nobody else raises**, such as "N flashcards due today", which is a reminder
rather than a static link. "It makes the page richer" and "the dashboard looks empty" are not
reasons. The default is to cut; adding a block is a question to ask before building it.
