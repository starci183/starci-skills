# Input

One frontend intent and mission identity, including a complete frozen multidimensional `scope` and
exact cross-domain resume when present. Frontend UX/UI scope includes one
`frontend.ux-ui.change-level` dimension with `refine`, `reconstruct`, or `new`, plus one
`frontend.layout.owner-ceiling` dimension. `layoutOwnerCeiling` resolves the target owner, mutable
nested layouts, feature-owned/directly nested page-modal-drawer owners, explicitly authorized mutable
ancestors, and immutable/excluded owners. For audit intent this direct feature owner group is compiled
in full before capture; shared branches and global/ancestor owners remain exclusions. Every exact file
declares its owner and may belong only to the mutable set permitted by that ceiling. A required shared
finding is routed to the Control Panel for owner permission after all independent in-scope work
continues; it is never bypassed by recreating shared behavior inside a local owner.

Local runtime evidence references the centralized runtime owner's current ready receipt. This input
never grants listener/process mutation authority: restart, server-environment, and port requests are
routed to the Control-Panel-delegated runtime task instead of being executed by the FE mission.

`auditTargetScore` is `null` unless the user explicitly requests a numeric audit target. A supplied
integer from 1 through 9 is a noncanonical progress target: it never replaces the typed visual
verdict, but it must be preserved across repair, cross-domain CALL/RETURN, recapture, and rescore.
`auditScoreHistory` is the ordered immutable ledger appended after each complete review. Every entry
binds its round score and delta to the typed verdict, latest source, reviewed evidence, and optional
finding batch; resumes must carry the entire ledger without rewriting prior entries.

For every in-scope application owner classified as `page`, `layout`, `modal`, or `drawer`, resolve one
adjacent lowercase `audit.md` artifact according to `knowledge/frontend-owner-audit.md`. Existing
records are passive evidence and owner-feedback context, never authority to reuse a stale verdict.
