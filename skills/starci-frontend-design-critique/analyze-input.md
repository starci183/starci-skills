# Analyze design-critique input

Require one immutable candidate, its hash, fresh business outcome, and exact source observations. Reject author reasoning transcripts and broad source context. Enter fixed state `critique`.

Bind the immutable candidate to the normalized scope record before critique. For `branch`, `journey`,
or `feature`, require rendered coverage to match the declared target set and applicable surface roles.
If candidate metadata could identify either one leaf surface or the whole scope and that difference
changes the verdict, return to global analysis for one focused clarification. Otherwise classify
under-coverage as revision or missing evidence; never silently critique only the visible page.
